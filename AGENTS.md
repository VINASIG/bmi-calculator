# VINASIG BMI Calculator

Read README.md, docs/PRODUCT.md, docs/RESEARCH.md, docs/BRAND.md and docs/TOOLCHAIN.md before changing this static Astro and TypeScript product.

- One repository contains two tools. The Vietnamese root checks only the BMI criterion for military recruitment. The English /en/ page uses CDC adult categories for people aged 20 and older. They share arithmetic, not conclusions. Do not treat these pages as translations or add reciprocal hreflang.
- Require only height in centimeters and weight in kilograms through direct text inputs with decimal keyboards. Do not add sliders, identity, date of birth, sex, accounts, telemetry, persistent health storage, remote calculation APIs or third-party requests.
- Research changes to medical or legal interpretation against current primary sources. Preserve the dated source record. Military BMI from 18.0 through 29.9 is inside the criterion under Circular 68/2025/TT-BQP, Article 1(1)(b), amending Article 4(3)(c) of Circular 148/2018/TT-BQP. This never establishes overall eligibility, a health grade, exemption or deferment. Do not recommend changing weight to influence recruitment.
- Classify exact decimal measurements with rational comparisons before rounding. Keep boundary tests around every threshold. Invalid input, edits, Clear and navigation must not leave a stale result. When scripts fail, disable submission and never serialize health fields into a URL.
- Adopt the shared Bright Playful Minimalism proposal, byte-preserved VINASIG exports, local Space Grotesk and Lucide. English technical documentation, source and commits accompany fully Vietnamese and English product pages. Respond to the user in Vietnamese. Use SI agents in VINASIG-authored descriptions.
- Run npm run check, npm test, npm run build and relevant Playwright tests. Open actual screenshots at the five standard sizes, 320 px, breakpoint neighbors and enlarged text. Check both routes, errors, all result bands, keyboard, touch, dark/reduced motion and script failure. Before authorized publication run performance checks, review staged changes, then verify remote HEAD, exact-commit CI, deployment and the live tools.
- Do not weaken quality gates, clip page overflow or hide functionality to pass. Preserve original assets and third-party notices. Public visibility grants no license. Store immutable before screenshots, reports and captures under ignored output/, with durable audits under docs/audits/.
- Report physical device use, screen readers, field metrics, fresh Codex discovery and independent SI-agent trials as NOT_RUN unless observed. Preserve sibling repositories and unrelated user changes. Commit, push and publication follow the user's current authorization.
